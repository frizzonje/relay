# Аудит каждого файла — план

> Детекция и уничтожение: повторы (DRY), грязь (чистый код), гонки. Проходим
> **каждый** из ~300 исходных файлов, а не только громкие. Разрез больших модулей —
> отдельным планом: [module-split.md](module-split.md). Фазы 2–3
> [architecture-cleanup.md](architecture-cleanup.md) этим планом не заменяются, а
> используют его чек-лист.

## Почему так, а не «прочитать и поправить»

Код здесь уже аккуратный: точных клонов 0.43% (jscpd), циклов импорта в api и sfu
нет, сервер почти везде перепроверяет состояние после `await`. Поэтому «на глаз»
остаётся только мелочь, а оставшиеся проблемы — системные. Это повторы одной
мысли, записанной разными словами (три помощника ack в web, 14 копий контракта
в api); комментарии, которые больше не правда; гонки в местах, где ресурс
регистрируется после `await` у владельца, который успел исчезнуть. Их ищет
сначала автомат, потом чек-лист, а сделанную работу закрепляет CI — иначе через
месяц всё вернётся.

## Чек-лист файла

Файл «чистый», когда по нему пройдены все пункты, а не когда в нём ничего не
бросилось в глаза. Пункт либо выполнен, либо записан находкой с `file:line`.

**DRY**

- D1. Ни одного типа, константы или функции контракта, объявленных заново: только
  импорт из `@relay/shared`. Своё — только то, чего у клиента нет (`ServerEntry`
  с `passwordHash`).
- D2. Ни одной второй реализации общего помощника (ack с таймаутом, разбор куки,
  санитизация ника, «повторить с отступом»).
- D3. Числа со смыслом — именованные константы; если число есть в контракте или
  в каталоге настроек — оттуда.
- D4. Повтор JSX и разметки (диалоги удаления и переименования, списки с
  поиском) — общий компонент, когда совпадает и поведение, а не только вид.

**Чистый код**

- C1. Комментарий — правда. Комментарий, описывающий мир до рефакторинга
  («api намеренно не тянет @relay/shared»), хуже, чем ничего.
- C2. Функция делает одно; > 60 строк кода — повод для разреза, > 150 — разрез
  обязателен (исключение: декларативные таблицы и каталоги).
- C3. Нет мёртвых экспортов, файлов и зависимостей (knip).
- C4. Нет приведений `as` у недоверенных данных без разбора; `!` — только там,
  где инвариант доказан строкой выше.
- C5. Ошибка не глотается молча: `catch {}` — только с комментарием, почему
  молчание правильно.
- C6. Имена говорят предметом, а не механикой (`handleX` у обработчиков Nest —
  исключение по соглашению).
- C7. Нет `eslint-disable` без причины рядом.

**Гонки и время жизни**

- R1. Проверка → `await` → действие: после `await` проверка повторяется или
  обоснованно не нужна.
- R2. Ресурс, созданный после `await`, привязывается к владельцу, только если
  тот ещё жив; иначе ресурс закрывается сразу (иначе утечка).
- R3. Каждый `emit` с ack на клиенте имеет срок (сокет может оборваться
  посреди запроса, ответ не придёт никогда).
- R4. Каждый таймер, слушатель и подписка снимаются при уходе владельца:
  `useEffect` возвращает уборку, сервис снимает своё в `onModuleDestroy`.
- R5. Асинхронный ответ, пришедший после смены контекста (другой канал, новый
  вход, размонтирование), отбрасывается по поколению или `AbortSignal`, а не
  применяется к новому контексту.
- R6. Нет висящих промисов: каждый `async` вызов либо ждут, либо явно `void` с
  обработкой ошибки внутри.
- R7. Одна очередь на один разделяемый ресурс (запись реестра — образец:
  `registry.service.ts`, `persist`).

Как идёт партия:

1. `node tools/report-size.mjs --inventory <каталог>` даёт для `docs/plans/audit/<партия>.md` таблицу
   файлов: строки кода, самая длинная функция, срабатывания детекторов.
2. Каждый файл читается целиком по чек-листу. Находка — строка в таблице:
   пункт, `file:line`, что не так, как чинить. Файл без находок отмечается
   явно — «прочитан, чист», иначе непрочитанный неотличим от чистого.
3. Для модулей с состоянием в памяти (все `new Map` в api/sfu, сторы web)
   отдельно выписывается: что за состояние, кто его меняет, где между
   изменениями стоит `await`. Гонки ищутся по этой таблице, а не по
   впечатлению.
4. Гонка чинится только после теста, который её воспроизводит: отложенный
   промис или фейковые таймеры задают порядок событий. Без красного теста
   починка гонки — гадание.
5. Коммиты — по одной категории на партию (`refactor(api): …`,
   `fix(sfu): …`), не «всё подряд в файле».
6. Партия закрыта, когда: все файлы отмечены, `turbo typecheck test build`,
   lint, format, docs:check зелёные, для 2.1/2.2/2.5 — e2e на стенде
