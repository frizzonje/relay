# Своя инсталляция

Установка, обновление, настройка и обслуживание сервера relay.

## Установка

Чистый **Debian или Ubuntu**, одна команда:

```bash
curl -fsSL https://raw.githubusercontent.com/frizzonje/relay/main/install.sh | bash
```

Что делает [`install.sh`](../install.sh): ставит Docker, спрашивает домен,
пароль входа, нужен ли TURN и медиасервер, пишет `/opt/relay/.env`, скачивает
готовые образы из GHCR, открывает порты в firewall, поднимает стек и ставит CLI
`relay`. Версия фиксируется в `RELAY_VERSION` — после перезагрузки `relay up`
поднимает то же самое. В конце печатается ссылка владельца.

Прочитать скрипт перед запуском:

```bash
curl -fsSLO https://raw.githubusercontent.com/frizzonje/relay/main/install.sh
less install.sh && bash install.sh
```

### Что нужно машине

| | Минимум | Зачем |
|---|---|---|
| CPU / RAM | 1 ядро, 1 ГБ | стек настроен под такую ВМ: Postgres с `shared_buffers=64MB`, `max_connections=30`, без параллельных воркеров |
| Swap | **2 ГБ** | без него первый нагруженный вечер кончается OOM-киллером и «случайными перезапусками» |
| Диск | ~3 ГБ | образы, база, загрузки |
| Порты | см. [Firewall](#firewall) | |

Медиасервер (`sfu`) ест CPU пропорционально числу видеопотоков — для звонков
4+ с камерами лучше 2 ядра.

### Без домена

Установщик возьмёт сертификат Let's Encrypt на IP-адрес сервера: настоящий
`https://<ip>` без предупреждений. Такие сертификаты живут 6 дней (профиль
`shortlived`), Caddy продлевает их сам. Режим записан в `RELAY_TLS_MODE` и
файле `tls-mode.caddy` ([`infra/tls-mode-ip.caddy`](../infra/tls-mode-ip.caddy)).
Не вышло (закрыт порт 80, адрес за NAT) — стек поднимется с самоподписанным
сертификатом (`issuer internal`).

coturn читает сертификат из тома Caddy и перечитывает его по `SIGUSR2` после
каждой ротации ([`infra/coturn-entrypoint.sh`](../infra/coturn-entrypoint.sh)).

## CLI `relay`

Стек живёт в `/opt/relay`. Исходник CLI — [`infra/relay-cli.sh`](../infra/relay-cli.sh).

| Команда | Что |
|---|---|
| `relay up` / `down` / `restart` / `ps` | обёртки над `docker compose` |
| `relay logs [сервис]` | логи (`api`, `web`, `sfu`, `caddy`, `coturn`, `db`) |
| `relay version` | установленная версия, последняя доступная, активные профили |
| `relay update [-y] [версия]` | перейти на новую версию (или указанную — так же делается откат) |
| `relay config` | открыть `.env` в редакторе, потом `relay up` |
| `relay backup` | тома + конфиг (включая `.env`) в один архив в `backups/` |
| `relay restore [-y] <файл>` | вернуть архив целиком |
| `relay owner-link` | новая ссылка владельца (24 ч, одноразовая) |
| `relay disown [id\|--all]` | отвязать сервер/канал от устройства-создателя — если тот браузер потерян |

## Обновление

`relay update` двигает не только образы: он заново скачивает с тега новой
версии `docker-compose.prod.yml`, конфиг Caddy, точку входа coturn и сам CLI,
затем `pull` и перезапуск. Прежние файлы остаются в `/opt/relay/backups/`, не
поднявшееся обновление откатывается само.

**Мажорное обновление** рассказывает, что изменится для людей, делает полный
бэкап и ждёт `yes` (`-y` — для скриптов). Откат — `relay update <старая версия>`
и `relay restore <архив, который оно сделало>`.

Установки, сделанные до появления этого механизма, имеют CLI, который умеет
только тянуть образы. На них один раз перезапустите установщик — он сохранит
`.env` (старый положит рядом).

### С 0.x на 1.0+

1.0 добавил в стек Postgres, а сервис образ с собой не принесёт. Поэтому тег
`:latest` на 1.0 **не** переведён: 0.x-сервер, следующий за `:latest`, остаётся
на 0.x. Переход — та же команда установщика: он сохранит `.env`, добавит базу,
сгенерирует её пароль и поставит новый CLI. Сделайте `relay backup` перед этим.

Что заметят люди: история перестаёт пропадать при рестарте и хранится
`RETENTION_DAYS` дней; каждый заново выбирает имя (человек теперь — ключ на
устройстве, а не строка в браузере). Серверы, каналы, файлы и сертификаты
переезжают как есть (`registry.json` импортируется в базу один раз).

## Конфигурация (`.env`)

Шаблон с комментариями — [`.env.example`](../.env.example). Большая часть
поведения настраивается не здесь, а в [панели владельца](#панель-владельца);
`.env` — это инфраструктура и секреты.

| Переменная | По умолчанию | Что |
|---|---|---|
| `SITE_PASSWORD` | пусто | пароль входа. Пусто — вход открыт. Пароль, заданный в панели, главнее этой строки |
| `POSTGRES_PASSWORD` | — | **обязателен**. Генерируется установщиком. Postgres читает его один раз при создании тома — менять потом нельзя |
| `DATABASE_URL` | из `POSTGRES_PASSWORD` | только для внешней базы |
| `RETENTION_DAYS` | `14` | срок хранения сообщений: число дней, `0`/`forever` — вечно, `ephemeral` — не хранить. Читается один раз, дальше — панель |
| `UPLOAD_MAX_TOTAL_BYTES` | `2GB` | потолок каталога загрузок (засевает `files.installQuotaBytes`) |
| `DOMAIN` | `localhost` | имя для Caddy: `localhost` — внутренний CA, домен — Let's Encrypt |
| `SERVER_HOST` | `localhost` | адрес для ICE-кандидатов и realm coturn |
| `TURN_SECRET` | пусто | общий ключ api и coturn для временных учёток. Нужен с `--profile turn` |
| `TURN_TTL_SECONDS` | `86400` | срок TURN-учётки |
| `TURN_EXTERNAL_IP` | пусто | публичный IP за 1:1 NAT (облачные ВМ) |
| `TURN_USERNAME` / `TURN_CREDENTIAL` | `webrtc` / пусто | статическая пара — только для чужого TURN, если нет `TURN_SECRET` |
| `STUN_URLS` / `TURN_URLS` | — | заменить список ICE-серверов целиком |
| `SFU_SECRET` | пусто | общий ключ api и sfu. Пусто — режим `sfu` выключен, все каналы звонят напрямую |
| `SFU_ANNOUNCED_IP` | `TURN_EXTERNAL_IP` | публичный IP в кандидатах медиасервера |
| `SFU_RTC_MIN_PORT` / `SFU_RTC_MAX_PORT` | `40000` / `40100` | порты медиа SFU: каждый воркер слушает один свободный порт из диапазона (UDP и TCP), воркеров не больше, чем портов |
| `SFU_URL` | `/` | адрес сигналинга SFU для клиентов; `/` — тот же origin, путь `/sfu/` |
| `SFU_INTERNAL_URL` | `http://host.docker.internal:3100` | откуда api проверяет, жив ли SFU |
| `SFU_WORKERS` | число ядер | воркеров mediasoup |
| `RELAY_VERSION` | `latest` | тег образов в `docker-compose.prod.yml`; установщик фиксирует версию |
| `RELAY_REPO` / `RELAY_REF` | `frizzonje/relay` / `main` | откуда `relay update` берёт файлы стека |
| `RELAY_TLS_MODE` | пусто | `domain`, `ip` или `selfsigned` — какой `tls-mode.caddy` класть при обновлении |

Профили compose: `--profile turn` (coturn), `--profile sfu` (медиасервер).

### Firewall

| Порт | Протокол | Для чего |
|---|---|---|
| `80`, `443` | TCP | Caddy: сайт, API, ACME |
| `3478` | UDP + TCP | coturn |
| `5349` | TCP | TURN over TLS |
| `49160–49200` | UDP | relay-диапазон coturn |
| `40000–40100` | UDP + TCP | медиа SFU |

Установщик открывает их сам. Порт сигналинга SFU (`3100`) наружу не нужен —
Caddy проксирует `/sfu/`.

## Панель владельца

Большая часть настроек живёт не в файле, а в панели — щит в тулбаре, виден
только владельцу. Владелец один; власть берётся ссылкой:

```bash
relay owner-link
# из исходников:
docker compose run --rm api node dist/owner-link.js
```

Открывший ссылку становится владельцем, прежний перестаёт им быть. Этим же
возвращают инсталляцию, если ключ потерян.

В панели:

- **Настройки** — около сотни параметров в 13 группах: доступ, люди, модерация,
  сообщения, файлы, ЛС, пространства, голос, звонки, приглашения, оформление,
  уведомления, обслуживание. Под каждым полем написано, когда правка вступит в
  силу. Полный список с границами и умолчаниями —
  [`packages/shared/src/settings.ts`](../packages/shared/src/settings.ts).
  Адреса и ключи TURN/SFU остаются в `.env` — панель их только показывает.
- **Люди** — все личности, их устройства и отпечатки; отзыв устройства, бан.
- **Баны** — баны на всю инсталляцию. Блокировка по адресу —
  настройка `access.blockedAddresses` (IP и CIDR).
- **Обслуживание** — экспорт/импорт настроек, ретенция вручную, уборка файлов,
  выход всех устройств, новая ссылка владельца.
- **Обзор и журнал** — нагрузка машины, число людей и сообщений, кто что
  менял и когда.

Секреты (пароль входа, ключи TURN/SFU) панель показывает только как «задан /
не задан» — ни в интерфейсе, ни в журнале, ни в экспорте их нет.

## Данные

| Что | Где | Переживает рестарт |
|---|---|---|
| серверы, каналы, личности, настройки, журнал | Postgres, том `pgdata` | да |
| сообщения | Postgres, пока не истёк срок хранения | да |
| вложения | том `uploads` + строка в базе | пока жива реплика |
| TLS-сертификаты | том `caddy_data` | да |
| отметки чтения, звук канала, громкость собеседников | Postgres, привязаны к личности | да, на всех устройствах |
| микрофон, камера, хоткеи | `localStorage` браузера | только на этом устройстве |

### Срок хранения

| `RETENTION_DAYS` / настройка | Что происходит |
|---|---|
| число > 0 | сообщения живут столько дней, чистка раз в час |
| `0`, `forever`, `never` | ничего не удаляется по возрасту |
| `ephemeral` | ничего не хранится, чистка раз в минуту |

Файл удаляется вместе с сообщением. Неприкреплённая загрузка — через сутки.
Закреплённые сообщения не удаляются (до 50 на канал). На каждом старте api
пишет в лог словами, что происходит с историей: `relay logs api`.

### Бэкап

`relay backup` кладёт в один архив дамп базы, оба тома и конфиг рядом с ними
(`.env` со всеми секретами, compose-файл, конфиг Caddy). Машина, поднятая из
такого архива через `relay restore`, возвращается как была. Храните архив как
секрет.

## Приватность

relay — не end-to-end-шифрование, а сервер, который принадлежит вам.

| | В пути | Читается на сервере |
|---|---|---|
| браузер ↔ сервер | TLS | — |
| голос и видео в канале `p2p` | DTLS-SRTP напрямую между участниками | нет, медиа до сервера не доходит |
| то же через TURN | DTLS-SRTP, TURN пересылает шифрованное | нет |
| голос и видео в канале `sfu` | DTLS-SRTP до медиасервера и обратно | да — SFU расшифровывает, чтобы маршрутизировать |
| сообщения, ЛС, вложения | TLS | да — лежат в Postgres и томе `uploads` открытым текстом |

Отсюда: кто имеет root на сервере, тот читает переписку. Это осознанный
размен — поиск, модерация и история для новичков без него невозможны. Почему
E2EE отложено — [plans/old/relay-1.0.md](plans/old/relay-1.0.md). Минимум следов —
`ephemeral` плюс каналы `p2p`.
