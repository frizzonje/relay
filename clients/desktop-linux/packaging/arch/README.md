# Arch Linux packaging

Arch has no `.deb`/`.rpm`, so the Linux client is shipped the idiomatic way: a
**PKGBUILD published to the [AUR](https://aur.archlinux.org/)**. This is the
source of truth, versioned with the code; on each release it is copied to the
matching AUR git repo.

| Package                                           | What it does                                                                      | Needs a toolchain? |
| ------------------------------------------------- | --------------------------------------------------------------------------------- | ------------------ |
| [`relay-desktop-bin`](relay-desktop-bin/PKGBUILD) | Repackages the official `relay_<ver>_linux_x86_64.AppImage` release asset into /opt | no                 |

There is no from-source recipe any more. The client is an Electron shell
(`clients/desktop-linux`), and building Electron from source on a user's machine
is hours of compilation for a byte-identical result — every AUR Electron app
repackages the upstream binary the same way.

Runtime deps are the Chromium ones (`gtk3 nss alsa-lib libxss libnotify`), not
the WebKitGTK stack: the AppImage carries its own engine.

## Why no native `.pkg.tar.zst` from CI?

electron-builder emits an AppImage but not pacman packages, and Arch users
expect to `paru -S relay-desktop-bin` rather than keep a downloaded AppImage
somewhere in their home directory. The AUR is the native distribution channel,
so that's where the package lives, and it reuses the AppImage the release
already ships — no extra CI build needed.

## Install (end user)

> [!NOTE]
> The package is not published to the AUR yet — the command below will only work
> once the recipe is pushed to its AUR git repo. Until then, build it from this
> directory (see "Test a PKGBUILD locally").

```bash
paru -S relay-desktop-bin      # or `yay -S …`
```

## Test a PKGBUILD locally

```bash
cd relay-desktop-bin
makepkg -si                    # build + install
namcap PKGBUILD                # lint the recipe
namcap relay-desktop-bin-*.pkg.tar.zst   # lint the built package
```

`makepkg` refuses to run as root — use a normal user. CI lints both recipes on
every push (see [`desktop.yml`](../../../../.github/workflows/desktop.yml), job
`arch`).

## Cut a release

After a `desktop-v<ver>` release is published (installers uploaded), on an Arch
box:

```bash
./release.sh                   # version from src-tauri/tauri.conf.json
# or: ./release.sh 0.3.8
```

This bumps `pkgver` in both PKGBUILDs, pins the `-bin` checksum with
`updpkgsums` (downloads the AppImage and records its real hash — the committed
template keeps `SKIP` because the file doesn't exist until the release is out),
and regenerates each `.SRCINFO`. Needs `base-devel` + `pacman-contrib`.

## Publishing to the AUR

`.SRCINFO` is generated by `release.sh`; it is **not** committed here (it only
belongs in the AUR repo, where it must exactly match the PKGBUILD). The AUR repos
are separate from this monorepo:

```bash
git clone ssh://aur@aur.archlinux.org/relay-desktop-bin.git
cp relay-desktop-bin/{PKGBUILD,.SRCINFO} relay-desktop-bin.git/
cd relay-desktop-bin.git && git commit -am "upgpkg: <ver>-1" && git push
```

The first push of a new package name also creates it on the AUR. Set your own
`# Maintainer:` line before publishing.
